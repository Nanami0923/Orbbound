# ORBBOUND Android 5.0.0 竖屏布局与界面重构方案

> 实施状态：方案由 5.1.0 承接发布，5.0.0 未单独公开；实际验收范围见 [5.1.0 验收记录](../releases/5.1.0-validation.md)。

日期：2026-10-19<br>
状态：5.0.0 实施与验收依据；开发基线为 4.7.0，本轮构建、设备及交付结果见 5.0.0 发布验证记录。<br>
关系：这是 [Windows 5.0.0 方案](Windows-5.0.0界面与动效重构方案.md) 的 Android 配套方案。两端共用视觉语言，布局、输入和发布分别处理，并共同组成双端 5.0.0 规划。

## 1. 总体方向

沿用已认可的深海军蓝、适度提饱和度的六色哑光球、薄荷主操作、金色成功、珊瑚色警示。球体、发射器、按钮、数字和弹层与 Windows 5.0.0 同源；Android 竖屏按“信息在上、棋盘居中、拇指操作在下”重新组织。

本版重点是版面、可读性、操作稳定性和统一反馈。保留 14 列棋盘、物理与计分、存档 schema、联机规则及两套触控方式。

本轮修订：保留球面原有图案及 Windows 5.0.0 同源材质；信息栏优先保证基础分宽度，左两栏仍为大数值在上、小标签在下，但增加上下留白；下一球改为文字与球体左右并排，空间不足时增加整栏高度。普通、沉浸和联机共用这一布局。以下为后续修改要求；相关示意图已移除。

### 1.1 球面图案与双端材质

保留原有 ColorId 与符号的对应关系，以及中央图案下方原有的两个深色小圆点；图案不能因压低高光而一并消失。首页演示、棋盘、发射球、飞行球、下一球以及观战预览全部使用同一套图案和材质。

## 2. 已有能力与需要解决的问题

### 已经具备，继续继承

- Capacitor SystemBars 安全区、visualViewport 高度、原生 IME 状态、系统返回与后台保护。
- 按钮模式与沉浸拖拽模式；左右换位、发射键宽度 76–120px、操作区偏移、微调灵敏度。
- 默认 60 FPS、手动 30/90/120 FPS、独立清晰度、减少动态、音效/音乐/震动设置。
- 移动下一球组件、单机剩余空间测量、联机人数自适应与原生覆盖升级。

4.7.0 已有 Android 16 实体机覆盖安装、返回流程、下一球及四人对局记录；四人样本是 1 台实体 Android 与同一 PC 上 3 个生产 C# 客人，不是四台手机。5.0.0 必须重新验证，不能把这些能力写成从零新增。

### 本版重点修正

1. 首页演示与模式卡片需要重新分配高度，短屏不能靠缩字维持“全塞进一屏”。
2. 局内顶栏、HUD、棋盘标题和下一球分散占高，低频按钮应收进游戏菜单。
3. 联机“下一球独占一行”可合并，保留更大的本方棋盘与拇指区。
4. 样式中旧短屏规则与后加规则有优先级争用：style.css 约 710 行的非沉浸短屏选择器可高于约 930 行新规则，使 32/46/92px 轨道与 44/96px 子项并存。需统一规则并检查 computed layout；这是静态审查发现，尚未实测为具体设备故障。
5. 不能将 Windows 三列布局缩小后直接用到手机，也不能让装饰挤占操作和安全区。

```text
├──────────┼──────────┤

└──────────┴──────────┘

```

- 主体为单列，模式卡片使用 2×2；卡片统一样式，单张约 88–104px，高亮只给当前主要行动。
- 每张卡只放名称、短说明和必要进度；保留星级/关数、最高分、5/10 分钟选择和联机入口。没有存档时不放长期禁用的“继续”按钮。
- 常规竖屏演示区域约 140–180px，短屏先降到 88–112px；不让首页动画占掉半屏。
- 标题在短屏变成一行或两行较紧凑排版，正文保持可读字号。可用宽度不足或字体放大时，模式列表可变为单列。
- 首页采用“顶栏 + 中间单一滚动区 + 辅助导航”。短屏/大字体允许中间内容滚动；底栏不能遮住最后一张卡。
- 演示约 10–11 秒自动循环，不保留重播按钮、点击复位或“轻触重播”提示。页面不可见、开菜单或后台时停钟；减少动态时静态展示机制。

### 4.1 顶栏与 HUD

- 顶栏默认约 48px：模式/关卡、必要时间、一个游戏菜单入口。重开、设置、玩法、排行、结算和存档返回收进菜单。
- HUD 高度以约 64px 为起点，随内容增长；基础分、模式相关约束、下一球并排。取消原先 52px / 短屏 40px 的压缩方案，上下留白不能为了凑固定高度被挤掉。
- 基础分优先分配宽度，不强制三等分。以 360px 视口、左右各 12px 的 336px 信息栏为例，可先按约 **144 / 92 / 100px** 分给基础分、距下压和下一球；栏内各自保留横向内边距。分数变长时可继续压缩旁边两栏的余量，前提是下压数值、单位、标签以及“下一球＋球体”仍完整可读。不能先缩小分数字号、加省略号或截断真实分数。
- 左两栏保留“数值在上、标签在下”，核心数值统一字号、上沿和基线，使用同一数字字形和等宽数字。常规数值约 24–26px、标签约 11px，本轮示意图采用 26px；上下留白约 12–14px，可见数值与标签之间约 6px，正式实施按实际字体与行高重测总高度。数值前置不等于贴着顶边，标签也不能贴底边。
- 无尽模式的“3”与“次”同一基线，单位约 11–12px，弱于数字；标签统一写“距下压”。这里按发射次数递减，不画成 `00:03`。限时模式同时保留距下压发射次数与本回合倒计时，不能用其中一项替掉另一项；窄屏放不下时允许 HUD 增高，仍让各组数值靠上。
- 下一球改为 **左侧“下一球”文字、右侧球体**，同一行垂直居中，二者间隔约 8–12px；球体约 26–28px，保留原图案与下方小圆点。取消“球在上、标签在下”的排法。它在自己的栏内整体居中，不靠外圈发光强调；常态只让基础分、球色承担主要颜色，下压临界状态再提升为珊瑚警示。
- 短屏先收区域间距和装饰，信息栏仍以约 64px 为起点，不再另设把上下内容压紧的 40px 档。长分数、限时双约束或系统大字体放不下时，先重新分配三栏宽度；仍不足就增加 HUD 高度并按需分组换行，下一球内部始终保持左右排布。重新实测棋盘空间，不用固定高度裁掉数字、单位或标签。
- 局内不再放一整套品牌、宣传说明或永久快捷教学。首次操作提示短暂出现，详细说明在菜单。
- 联机和单机使用同一下一球组件及装填时序，始终只显示一份。可另评估把下一球移到炮台附近，但本方案首选 HUD 固定位置，避免窄屏覆盖炮管、瞄准线或手指。

不同模式的语义必须明确：

| 模式 | 顶栏时间 | HUD 中间信息 |
| --- | --- | --- |
| 无尽 | 本局用时 | 距下压还可发射 N 次 |
| 限时 | 全局剩余时间 | 距下压发射次数 + 本回合倒计时，两项同时保留，必要时增高并上下分组 |
| 闯关 | 该关实际时间约束；无时限时可显示用时 | 剩余发射次数或目标进度 |
| 联机 | 对局剩余时间 / 状态 | 实际波次、压力或攻击状态，按玩法选择 |

关卡剩余弹数、下压次数、全局倒计时是不同约束，不共用误导性标签。只有实际存在下压的关卡才显示下压预警。

### 4.2 棋盘大小：按剩余空间计算，不拉伸

原游戏逻辑尺寸为 640×760、14 列、球半径 18、发射器中心 (320,708)。这些不随 UI 调整。

```text
可用宽 = 实际视口宽 − 左右安全区 − 左右内容边距
可用高 = 实际视口高 − 上下安全区 − 上下内容边距

棋盘区高度预算 = 可用高
               − 顶栏实测高度 − HUD 实测高度
               − 操作区实测高度 − 区域间距

棋盘宽 = min(可用宽, 棋盘区高度预算 × 640 / 760)
棋盘高 = 棋盘宽 × 760 / 640
```

延续现有 ResizeObserver + 实测方式。上式用于说明预算，生产代码不硬写统一扣减值；字体、HUD 增高、菜单状态和用户操作区偏移变化后重新测量。

默认尺寸建议：

| 区域 | 常规竖屏 | 紧凑竖屏 |
| --- | --- | --- |
| 顶栏 | 48px | 48px |
| HUD | 约 64px 起，数值/标签留足间距，下一球左右排布 | 同样约 64px 起，不压缩上下留白；内容不足可增高 |
| 按钮操作区 | 104px | 100px |
| 3 段间距合计 | 24px | 18px |
| 上下普通内容边距合计 | 16px | 12px |

紧凑档以扣除系统安全区后的实际可用高度小于约 600px 为起点，只压缩其他区域的冗余占位，不将 HUD 恢复为紧贴上下边缘的排法。字号放大后行高允许增长，优先收装饰和次要文字，不能固定高度裁字。

以下是更新为 64px HUD 后的规划预算示例，不是真机测量；假设左右各 12px、操作区额外偏移为 0，常规非棋盘占高合计约 256px、紧凑约 242px；HUD 实际增高后还需重算：

| 视口 CSS 尺寸 | 假设上下安全区和 | 档位 | 棋盘约宽×高 |
| --- | --- | --- | --- |
| 320×568 | 48px | 紧凑 | 234×278 |
| 360×640 | 48px | 紧凑 | 295×350 |
| 360×800 | 48px | 常规 | 336×399 |
| 393×851 | 56px | 常规 | 369×438 |

14 列决定了棋盘的宽度上限：例如 360 宽减去左右各 12px，最大棋盘高约 399px，无法在不变形的情况下铺满长屏高度。长屏剩余空间用作安静留白和可调手位缓冲；短屏优先缩减非必要占位，保留完整棋盘。不要改列数、物理半径、失败线或弹道来“适配”。

### 4.3 底部操作区

- 保留双滑杆 + 大发射键。两条滑杆各有约 48px 触控行，方向/微调名称缩短，完整解释放帮助页。
- 发射键宽度继续尊重用户 76–120px 配置；左右换位后，视觉、命中区和焦点顺序一起改变。
- 控制区固定在底部安全区之上，不随棋盘等比缩小，不进入系统手势区。
- 用户操作区偏移继续保留；短屏只限制当次实际可用偏移，不偷偷改写已保存偏好。
- 默认图标按钮至少按 48dp 触控目标验收。CSS px、Android dp 和物理像素不能混用，WebView 需结合 viewport/密度和真机命中检查。[Android 触控目标建议](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views)

## 5. 沉浸操作竖屏

顶部与 HUD 保持一致，移除双滑杆和大按钮；棋盘可使用回收的高度，底部仅留简短操作提示/取消状态。

- 与普通模式共用本轮上提后的数值 HUD、六种原有球面图案、下一球和发射器，不另做一套皮肤。菜单入口仍在顶栏，详细操作说明放在菜单内。
- 常驻操作提示为“按住瞄准 · 松手发射”，次行说明“移出棋盘松手取消”；不同时显示按钮模式的教学。按住时才出现轻量触点和瞄准路径，松开后触点消退，避免手指附近堆叠光效。
- 完整棋盘依旧按 640×760 等比绘制。回收控制区后重新实测可用高度；宽度已达到上限的长屏主要减少操作面板、保留留白，不拉长棋盘或改变球距。取消操作区不等于取消底部系统安全区。
- 瞄准命中区仍与实际棋盘容器一致；底部提示和系统安全区不扩成新的发射区域。示意图中的虚线是瞄准预览，触点是手势状态说明，不是新增按钮。
- 保留 Pointer Capture、指针所有权、待发射最多 1 发与当前超时策略。
- 待发射标记要可见、可取消，不能让玩家误以为刚才没发出去。
- 旋转、换输入模式、开菜单、后台、取消手势及重连时清空拖拽/微调/缓存发射；回来后不补射。
- 沉浸模式由用户选择。短屏不强制切模式，也不强制横屏；长屏即使空间增加，棋盘仍受宽度约束，不承诺必然变大。
- 滑杆/发射区在按钮模式下不抢系统滚动，棋盘只在沉浸手势有效时接管对应触控流。

## 6. 联机竖屏

推荐从上到下：紧凑顶栏 → 本方分数/下一球 HUD → 一排对手摘要 → 本方棋盘 → 原有操作区 → 安全区。

- 取消“下一球独占一行”；本方棋盘优先，不在竖屏保留 Windows 右侧栏。
- 1–3 个对手按真实人数分配，一排最多 3 张。只常驻名字、分数、波次/状态，缩略棋盘作为次级可选信息；不放空玩家卡。
- 压力、攻击、剩余时间和网络异常保留，但不堆成多个高面板。延迟/连接状态可用紧凑摘要或菜单详情，异常时提升可见度。
- 观战切换后，主棋盘、下一球、分数和状态一起跟随所观战玩家；恢复自己后再启用自己的输入。
- 对手详情只读查看不等同全局暂停。仍按现有投票/房主规则处理暂停，不能因新弹层擅自冻结对局。
- LAN resize 建议先统一 resetInput 再排版，补强旋转后旧指针矩形、捕获和待发射清理，保持单机/联机一致。

## 7. 菜单、结算、排行榜与关卡页

统一深色哑光面板、单层细边、主次按钮与数字字形；Android 的操作按钮不显示 Windows 键帽。

- 游戏菜单用易于拇指到达的底部面板或紧凑居中面板；不伪装可拖拽把手。继续游戏为全宽主按钮，常用操作成组，放弃/结算与继续拉开距离。
- 结算主按钮独占一行；次按钮最多两列，窄屏/大字体改纵排。关闭区、图标、中文和箭头独立布局，不再挤在同一小按钮上。
- 本地排行用单列记录：名次/分数为主，难度/日期/用时为次。筛选和分页保留；普通竖屏争取清楚显示约 5–6 条，实际按可用高度决定。
- 关卡列表普通手机可 4–5 列，窄屏或大字体减少列数；每格保留足够触控区域，星级不挤进关卡数字。
- 设置继续按类别进入详情，详情单一滚动；其他菜单沿用既有语义分页。禁止外层页面和弹层内容同时争抢滚动。
- 大字体先重排并允许滚动/分页，不把全局 transform:scale() 当作适配。

## 8. 安全区、键盘、返回与生命周期

安全区沿用现有唯一布局来源：Capacitor `SystemBars`（`capacitor.config.ts` 中 `insetsHandling: 'css'`）注入 `--safe-area-inset-*`，`src/ui/android-insets.ts` 映射为 `--safe-area-*`；SystemBars 变量不可用时才回退到 `env()`。`MainActivity` 通过 `WindowInsetsCompat` 将安全区和键盘状态旁路给 `GameFeedback`，同时把 Insets 原样传回，让 SystemBars 继续负责布局。不得增加第二套原生 padding、重复扣已缩小的 `visualViewport`，或把物理像素直接当 CSS 数值。

背景可延伸到系统栏下，按钮、文字和拖拽目标避开系统栏、刘海和手势区域；尤其底部发射区不能压在系统返回手势上。[Android 边到边设计](https://developer.android.com/design/ui/mobile/guides/layout-and-content/edge-to-edge)

- IME：优先现有原生键盘状态；浮动键盘也要识别。继续使用联机字段编辑层，先结束输入，再回到原菜单。键盘高度不再从已缩小的视口减第二次。
- 旋转/分屏：按当前可用宽高重排，不按手机型号或物理分辨率分档；保留同一局、随机序列、瞄准语义和倒计时，不重建游戏。[Android 可用窗口空间原则](https://developer.android.com/develop/ui/compose/layouts/adaptive/use-window-size-classes)
- Back：编辑/键盘先处理；设置子页回父页，模态回来源；LAN 沿用自己的退出确认；单机仍保留当前保存回首页；首页最小化。顶部菜单用于暂停，不在纯视觉改版中偷偷把 Back 改成另一种行为。
- 终局的关闭/系统返回仍回首页，设置和排行保留来源返回及筛选/页码，保存失败仍可重试。
- 后台：继承单机回首页保存与联机 foreground(false)；停止装饰动画/声音与输入，前台恢复不补跑和补射。
- 横屏仍提供棋盘左、信息与操作右的紧凑布局；不因主打竖屏删除横屏支持。

## 9. 动效与性能

- 与 Windows 共用发射/装填、消除/掉落、连击上浮、金色通关、珊瑚触底细波的语言；Android 降低粒子数量，不加整屏闪白或持续震动。
- 连击不改计分倍率，通关/失败只随真实事件触发。首页循环属于机制演示，正式局内不循环自动弹出胜败结算。
- 避免每帧新建材质、DOM 或大面积实时模糊；缓存球体、炮台和静态棋盘，单机 Phaser 与联机 Canvas 共用外观参数。
- 保留默认 60 FPS 和用户固定帧档；清晰度、帧率、震动、减少动态分别生效。本轮不顺带引入新自动升帧算法。
- 低动态省去粒子、位移、扩散和脉冲，保留文字/颜色/命中反馈；不得改变真实发射锁、限时难度或联机展示时钟。
- 低性能机与持续发热使用同机同设置对比帧时间/掉帧、耗电与触控响应，不能只看首页 RAF 数字或一次短测。

当前 `src/main.ts` 以 `usesButtonControls()` 切换通用 `.mobile-ui`；它不是 Android 平台或版本开关。5.0.0 应单独按 `Capacitor.getPlatform() === 'android'` 或明确开发预览标志启用 `.android-v5`，不能仅靠 max-width、pointer:coarse 或 `.mobile-ui` 激活新版本主题。跨端共用设计 token 和渲染配置，平台只决定布局与操作；独立阶段保留旧主题回退。

Android 正式版本拟为 versionName=5.0.0、versionCode=50000，保留 applicationId=com.orbbound.game、原签名和数据 schema。现状核对：`vite.config.ts` 给 Android 取根 `package.json` 版本、给 Windows 取 `electron/windows-package.json`；Android 打包脚本也用根版本命名输出，但 Gradle 当前仍是 `40700 / 4.7.0`，且打包前没有两处一致性校验。实施时需把根版本和 Gradle 同步到 `5.0.0 / 50000` 并增加校验。若双端允许独立推进，Windows 的 `scripts/package-win.cjs` 不仅要移除与根版本相等的断言，还要改为从 `electron/windows-package.json` 读取程序集、输出目录和压缩包版本；双端同步到 5.0.0 时该约束不会阻塞本轮目标。

维持现有 SDK/权限与存储路线，不因换皮增加权限或更换包名。旧存档、设置、记录与备份兼容；覆盖升级、联机协议/指纹及 Android ↔ Windows 混连都需重新实测后才可宣称通过。

## 11. 实施顺序与验收

实施顺序：
1. Android 专属主题与布局规则整理，做 393×851 常规竖屏基准。
2. 完成首页、按钮模式、沉浸模式；验证 360×640、320×568 和大字体。
3. 同步联机、关卡、排行、设置、结算和所有返回链路。
4. 接入低动态、输入重置与缓存，做性能和真机安全区。
5. 原签名覆盖安装、旧数据与双端混连，通过后才生成 5.0.0 APK。

版面目标：
- 局内无整页滚动、无横向溢出，棋盘/发射器完整显示，操作区与系统栏不重叠。
- 首页、菜单、排行与设置可按其各自策略滚动/分页，末尾动作始终可达。
- 宽 320/360/393/412，常见高度 568/640/800/851/915；同时测短横屏、分屏和可用区域突然变化。
- 字体 100% / 130% / 150% / 200%；关键数字不裁、目标与主要按钮不被省略。
- 手势/三键导航、刘海/挖孔、普通/浮动输入法、横竖切换与切后台。
- 左右换位、76–120px 发射键、操作区偏移、双指微调/发射、长按/取消/指针丢失及待发射超时。
- 下一球飞行/装填/观战同步，下降次数与剩余弹数不混淆；暂停/后台/旋转/菜单后无补射。
- 六种球面图案在首页、普通/沉浸/联机棋盘、下一球及发射球中一一对应；缩小和减少动态时仍保留。顶部两个核心数值上沿/基线一致，分数栏有优先宽度，上下留白充足；下一球文字与球体左右排布。长分数、单位和大字体不裁切，需要增高时棋盘随实测重排。

- 至少一台低性能机和一台高刷机，覆盖持续升温与 30/60/90/120 档；四实体设备联机单独记结果。
