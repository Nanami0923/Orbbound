## 3. 主页动画：用同一份几何生成路线和落点

### 3.1 正确落点

维持 SVG `viewBox="0 0 320 200"`、半径 `r=14`、发射点 `(160,165)` 和原有动画时序。

左侧两球的中心间距为 `2r=28`。发射球应落在两球中间下方的相切位置：

```text
x = (80 + 108) / 2 = 94
y = 40 + sqrt((2 × 14)² - 14²) = 64.248711...
位移 = (94 - 160, 64.248711... - 165)
     = (-66, -100.751289...)
```

落点到两个球心的距离都应为 28。不能简单把 x 改成 94、仍将 y 留在 68，否则两侧仍未正确贴合。

### 3.2 实施方式

- 提取小型纯展示几何定义，例如 `src/ui/home-demo.ts`，由球心和半径推导落点，不重复手写终点常数。
- 同时生成 SVG 虚线路径和 CSS 动画终点变量；飞行、停留、淡出阶段使用同一位移，重播和重置时不跳位。
- 延续点击/轻触重播、减少动态效果、前后台可见性与 4.5.0 已修复的演示显示行为。
- 右侧演示仍验证“黄色球相连消除 → 下方红球失去支撑掉落”的顺序。本项调整展示几何即可，不修改真实棋盘物理、吸附或得分规则。

验收：几何不变量测试，加浏览器动画停留阶段截图；对比两端 320px 起的小屏和桌面缩放，确保弹丸、符号与路线同步到达中间位置。

## 4. 关闭和返回：按页面语义统一入口

### 4.1 结果页离开动作

建立一个可复用的“离开终局返回首页”动作，由结果页右上角、底部首页、Esc、Android 返回键和允许关闭的遮罩入口共同调用。

1. 清空待发射、长按转向和本轮残留输入，关闭结果弹窗及分页/焦点监听。
2. 明确禁止 `resumeAfterModal` 恢复终局，不把已结束棋盘当作运行中的对局。
3. 回到首页、更新存档/历史提示并恢复主页焦点；终局棋盘隐藏，游戏循环休眠，音乐回到菜单状态。
4. 关闭不再次调用 `settleGame()`，不重复结算，不启动新局；重试、下一关、查看本榜保留各自明确入口。

闯关结果也统一“关闭回首页”；“返回选关”按钮继续明确返回选关，下一关与重试不受影响。结算前的确认弹窗仍可取消继续当前局，不能把确认前取消当作已经结算。

### 4.2 页面关闭行为矩阵

| 页面/来源 | 右上角或明确关闭 | Esc / Android 返回 / 可关闭的遮罩 | 保留的显式动作 |
| --- | --- | --- | --- |
| 无尽、限时终局结果 | 返回首页 | 返回首页 | 重试开新局；查看本榜先退出终局再展示排行 |
| 闯关终局结果 | 返回首页 | 返回首页 | 下一关、重试、返回选关 |
| 结算/重新开始确认 | 取消，返回来源游戏或菜单 | 同样取消 | 只有确认才结算/重开 |
| 游戏菜单内“放弃本局”确认 | 返回游戏菜单，继续暂停 | 返回游戏菜单，继续暂停 | 确认后才放弃 |
| 游戏菜单 | 继续游戏 | 继续游戏 | 存档并返回首页 |
| 首页模式配置、关卡选择 | 回首页 | 回首页 | 开局、续玩、查看排行 |
| 关卡详情 | 返回选关 | 返回选关 | 开始关卡；保留章节/页码 |
| 游戏菜单打开设置/历史 | 回原游戏菜单 | 历史回原菜单；设置详情先回分类 | 不提前恢复比赛 |
| 模式配置打开排行 | 回原配置页 | 回原配置页 | 保留难度、时长与存档选择 |
| 排名规则说明 | 回原历史/排行页 | 回原历史/排行页 | 保留榜单、筛选与页码 |
| 设置分类/详情 | “完成”提交当前设置并回来源 | 详情先回分类，分类再回来源 | 联机设置仍通知设置关闭状态 |
| 教程/练习 | 按打开来源返回上级 | 与已有 `onCancel` 语义一致 | 完成/跳过继续原计划，不误开两局 |
| 已有数据操作确认页 | 取消回发起该操作的页面 | 同样取消 | 仅执行该确认页对应操作；恢复默认设置沿用原操作，不新增二次确认 |
| 联机观战覆盖层 | 返回自己/当前对局 | 先关覆盖层 | 不离房、不触发本机发射 |
| 联机进行中离房确认 | 取消则留在比赛 | 返回键取消；背景不关闭 | 明确确认后才离房或关闭房间 |
| 联机结果 | 离房回首页 | 走同一会话退出链回首页 | 再来一局回大厅，不拆掉房间 |

教程底部等按钮文案须与来源匹配：首页打开时使用“返回首页”，局内直接打开使用“继续游戏”，有父级时使用“返回…”；避免文字与实际落点冲突。

### 4.3 实现边界

- 保留 `dismissModal()` 执行用户关闭策略、`closeModal()` 仅清理弹窗的职责区别；不将全局 `closeModal()` 一律改成回首页。
- 结果页传入明确关闭回调；取消确认、设置/历史等有父级的页面传入来源回调。分页、筛选、窗口重排重建时继续携带来源，不丢失返回目标。
- 程序化替换弹窗、重试、开始关卡等直接关闭清理，不误执行用户取消策略。关闭和清理应可重复调用，快速双击最多导航一次、开局一次。
- 终局记录固定首次成功保存的结束时间与结果；重复 `persistGame()` 不改写 `endedAt`。补上同一 `sessionId` 关闭前后分数、名次、时间与记录条数不变的测试。
- 核查结算写记录失败的返回值：保存失败应给出真实反馈并保留可恢复进度/结果，不在未确认写入时显示“已保存”并直接删除唯一可恢复副本；具体失败路径需实施时模拟验证。
- 设置离开继续执行保存、预览解绑及 `settingsOnClosed`，本方案不新增数据维护确认层级；联机继续走 `leave()/exit()`、待同步结果捕获和 `previous.close()`，不能直接调用单机首页函数跳过传输清理。
- 快速退出/重入、迟到异步结果、焦点恢复和 Android 返回键连按纳入回归；继续保留现有会话与原生 `_clientId` 隔离。

## 5. 文字排版：标题真居中，操作标签不被附件挤偏

### 5.1 对齐规则

| 内容 | 处理 |
| --- | --- |
| 主页主标题/副标题、模式卡标题 | 在所属内容区域居中；中文按语义换行，不靠空格补齐 |
| 普通弹窗、结果页、设置/练习标题 | 相对整个标题栏居中；左右操作位对称预留，长标题正常换行 |
| 普通单标签主按钮、次按钮、分页、分类入口 | 水平和垂直居中；保留足够点击高度 |
| 带图标、箭头或快捷键的按钮 | 文本占独立中间列，两侧辅助位独立布局；快捷键继续右对齐 |
| 信息统计 | 标签与数值在各自格内对齐，时间/分数使用等宽数字，更新不抖动 |
| 设置说明、教程正文、地址/昵称输入、日志、排行榜姓名 | 按阅读和输入需要起始对齐；不全局强制居中 |

### 5.2 实施方式

- 给弹窗建立统一标题栏结构，替换单侧 `padding-right:96px` 的避让方式；左返回与右关闭不论宽度是否相同，标题都围绕标题栏中线排列。
- 普通单标签按钮使用居中对齐；图标/箭头/`kbd` 按钮采用独立列。不要只给原 `justify-content:space-between` 按钮加 `text-align:center`。
- 保留 `headingLines()/formatHeadings()` 的语义分句；检查分句后的每行、两行标题和长按钮。避免固定按钮高度截断文本。
- 合并本次涉及的重复覆盖规则，按组件和平台档位维护；不在样式表末尾持续追加互相抵消的高优先级选择器。
- 验收依据是文字布局盒相对所属容器的几何居中及实际截图，无需用手工空格或单个字号的像素偏移修正。

## 6. 下一球：四模式共用一个预览规范

### 6.1 以现有单机样式为基准

共用 `next-card / next-preview / dom-orb` 的结构或等价共享组件；提取球直径、符号字号、预览容器、高光、阴影、标签和间距变量，删除联机独立的 28px / 14px / 36px 硬编码覆盖。

| 平台与档位 | 球直径基准 | 容器/行为 |
| --- | --- | --- |
| Windows 普通窗口 | 36 CSS px | 与现有单机侧栏预览一致，容器48px |
| Windows 紧凑短窗口（现有高度≤450px档） | 26 CSS px | 与单机共同进入紧凑档，容器28px |
| Android 标准/沉浸档 | 40 CSS px | 与单机共同使用44px预览容器 |
| Android 短竖屏、非沉浸档（现有高度≤700px档） | 30 CSS px | 与单机共同使用32px容器；触发条件完全相同 |

球面颜色、符号形状、高光和投影采用现有单机规范。当前单机 `::before` 符号实际为18px；在标准和紧凑档分别显式定义共享字号，不能只改父球 `font-size` 而遗漏伪元素。若紧凑档字号需要调整，四模式同时调整并做截图确认。

### 6.2 状态同步契约

- 共享的是展示组件与更新方法，不改变规则状态、随机数序列和发射队列。
- LAN 保留 4.6.0 的正确机制：从主画布实际绘制状态的 `drawnState.nextColor` 更新预览，不能改回从 `lan-panel` 读取最新权威快照直接更新。
- 验证本地预测、权威飞行、消除/装填、暂停恢复、重连、主图观战切换与返回自己；对手缩略图和弹出观战不得覆盖本机主预览。
- 单机在发射后即提交后态、飞行期间还会周期发送状态，存在提前更新预览的静态路径。抽组件时补阶段测试，必要时增加纯展示 `previewNextColor`，使预览在装填阶段与炮口同步切换；不推迟规则提交或存档。
- 预览信息条从顶部布局的实际可用高度中统一扣除，不额外叠一层预览，不挤压或遮住棋盘。

## 7. 联机顶部：信息分组清楚，把余量交给棋盘

### 7.1 信息优先级与结构

将昵称/得分、时间、网络、预警与对手区分成明确组件；使用有类名的节点定位，逐步替换依赖 `div:first-child` 的布局规则。建议组织如下：

```text
Android 竖屏
┌ 模式/房间                         离开 ┐
│ 本机昵称 · 分数      剩余时间      暂停/设置 │
│ 第 N 波              02:58        延迟 65 ms │
│ 预警/来袭摘要；有暂停申请时显示明确操作区     │
│ 对手1摘要       对手2摘要       对手3摘要    │
│                             下一球 [球]   │
│                 主棋盘                   │
└ 操控区 / 沉浸模式提示                    ┘

Windows 宽窗口
┌ 本机成绩        剩余时间/延迟       暂停/设置 ┐
│ 预警/投票提示                              │
│                 主棋盘       下一球预览    │
│                              对手缩略图列表 │
└ 操作提示 / 连接状态                        ┘
```

示意表示阅读顺序，不要求用固定行高复刻。

### 7.2 时间与延迟

- 时间数值、时间标签、延迟各有独立空间；取消“64px 内第二行同时放四字标签和 RTT”的结构。
- `剩余时间`、`02:58`、`延迟 65 ms` 各自不拆行，采用等宽数字。空间不足先将延迟移到次行或侧区，不拆成“剩余时 / 间”。
- 未收到网络样本显示明确占位/状态，沿用现有 RTT 数据语义；不伪造 0ms，也不因数值位数变化反复挤动按钮。

### 7.3 预警与暂停申请

- 正常压力/防御作为紧凑摘要；攻击预告、掉线恢复、暂停投票采用独立状态区，不与剩余时间混排。
- 不为没有内容的状态持续保留44px空槽；同类状态保持稳定高度，长内容在状态切换时一次性重排，避免每个 tick 跳动。
- 四人长昵称的投票消息允许正常换行，确认/拒绝按钮保持可见、可点；不得用省略号隐藏必须处理的申请，也不遮住发射控件。
- 正常状态摘要精简时仍保留必要的预警信息；不通过删除攻击/断线提示为棋盘腾位置。

### 7.4 对手与不同屏幕

- Windows 对手列表沿用右侧竖排，统一缩略图比例、姓名、分数和状态基线；窄窗口按可用空间切换紧凑布局。
