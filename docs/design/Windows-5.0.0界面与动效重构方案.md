日期：2026-10-19<br>
状态：5.0.0 实施与验收依据；开发基线为 4.7.0，本轮构建、设备及交付结果见 5.0.0 发布验证记录。<br>
范围：Windows 5.0.0 方案，与 [Android 5.0.0 竖屏方案](Android-5.0.0竖屏布局与界面重构方案.md) 共同组成双端规划。视觉 token 同源，平台布局、输入与发布分别验收；4.7.0 原包、源码和用户数据保持原状。

本文作为正式应用的修改要求；预览不能替代真实应用、安装包和设备验收。

## 1. 视觉目标与本轮定稿方向

延续已认可的简约 Demo：深海军蓝底、哑光球体、薄荷色操作、金色成功、珊瑚色警示。比上一版 Demo 稍加饱和度，整体仍低于最初鲜艳方案；维持低高光与低反差明暗，不重新加入白亮点、霓虹外光、多层金属描边。

本轮预览色板作为实施起点：

| 主要操作 | #83CDB5 | 深色字，整页一致 |
| 成功 / 警觉 | #DDBA62 | 小面积使用 |

球体浅部只作少量同色提亮，暗部用深蓝压低体积；棋盘单层细边，圆角约 18–22px，按钮约 10–12px。数字使用等宽数字特性，中文统一系统无衬线字族。正式 Windows 实施以 13–14px 正文/按钮、11–12px 辅助标签为起点，关键数据 28–40px，避免把原型里的小字直接照搬到原生窗口。

## 2. 首页重做

桌面首页保持左右两栏：左侧品牌、主标题“瞄准，让它掉落。”、机制说明与自动演示；右侧用统一模式列表容纳无尽、闯关、限时、局域网联机。主模式用低饱和薄荷底区分，其余卡片用深色底和小面积图形，不再同时出现多个高亮大按钮。

实际游戏必须保留现有入口 ID、闯关进度/星级、无尽最高分、限时 5/10 分钟选择、各模式存档状态以及联机入口。辅助入口统一为玩法、设置、历史与排行；没有存档时不增加长期禁用的大按钮。

预览首页底部还展示“局内动效”入口；它只用于评审，正式首页保留玩法、设置与历史/排行入口，不加入这个观察按钮。

首页演示改为非按钮的 figure/div，不获得焦点，不响应点击复位：
- 自动循环“瞄准 → 发射 → 三球消除 → 断支撑掉落 → 短暂停留 → 恢复”。预览当前周期为 10.8 秒；正式首页可沿用约 10–11 秒节奏。
- 动画持续自动循环，不需要点击“重播”。
- 删除“点击/轻触重播”文字与带重播语义的 aria-label；图示本身保留描述性无障碍文本，并移除重置 animation.currentTime 的事件。
- 首页离开、模态打开或页面不可见时停钟；恢复时继续，不补跑大量帧。原生窗口失焦/最小化的暂停与恢复属于 Windows 验收项，浏览器预览不能代替验证。
- 减少动态效果时改为静态机制图，保留信息，停止持续位移。

当前 `src/ui/home-demo.css` 的核心演示已是 10 秒 infinite CSS 循环，另有 32 秒交替漂移的背景轨道；`src/ui/home-demo.ts` 仍输出带重播 aria-label 的按钮，`src/ui/home.ts` 也注册点击后重置动画的处理。Windows 目标保留现有几何与 CSS 循环方式，只移除首页演示的按钮语义和重播处理，并让低动态模式停掉背景漂移；Android 当前行为另行保留。

## 3. 局内与所有页面统一

| 区域 | Windows 5.0.0 改造 |
| --- | --- |
| 左侧 HUD | 品牌、基础分、计时、距下压发射次数、个人最佳；标签、数值、间距统一 |
| 棋盘 | 内凹深色底与一层低对比边界；保留实际几何、瞄准落点与反弹 |
| 发射器 | 简洁底盘与短炮管；用轮廓和中间色区分体积，保持清楚可见 |
| 下一球 | 单独的安静预览座；移除轨道光圈，DOM 和 Canvas 使用同一色板与符号 |
| 右侧工具 | 图标、中文、快捷键分区；统一高度，悬停仅底色变化与约 1px 上移 |
| 暂停 / 设置 / 玩法 | 同一弹层骨架、关闭键、主次按钮、焦点与返回行为 |
| 结算 | 统一分数和数据模块；通关用少量金色，失败用珊瑚色；保留保存失败重试 |
| 本地排行 | 分数、名次最突出；保留玩法/难度/规则筛选、分页和来源返回 |
| 联机大厅 / 对战 | 沿用同一面板、字体、下一球与按钮规范；保留对手布局、观战、延迟/状态信息 |

当前原型右侧工具栏为“暂停游戏 / P、重新开始 / R、游戏设置 / S、历史与排行 / H、玩法提示 / I”；其弹层展示暂停、设置、玩法、示例排行、局域网说明、通关与失败。局域网页只作说明，不连接网络；排行榜是示例数据，正式版仍接现有分页与筛选。

必须分清两个提示：剩余发射次数表示“距棋盘下压”，触底线表示“失败边界”。不能把前者改画成生命值，也不能因为棋盘较低就把剩余 6 发伪改为 1 发。

保留 Esc 存档返回首页、F 结算、R 重开、S 设置、H 历史、I 帮助、空格发射、方向键/Q/E 瞄准、F11 全屏。新增暂停入口可默认 P，但要检查已有自定义键位冲突，不覆盖用户设置；界面键帽读取实际绑定。终局 Esc/关闭等仍按既有导航来源返回，不能被通用“暂停”处理吞掉。

## 4. 动效规范

| 场景 | 表现 / 建议时长 |
| --- | --- |
| 按钮 | 120–160ms，底色变化与 1px 位移；无发光边框 |
| 发射 / 装填 | 约 140ms 后坐、220ms 装填；装饰不延迟真实发射或随机序列 |
| 下压临界 | 最后 2 发暖金，最后 1 发短提示；与实际次数同步 |
| 触底风险 | 底线低强度脉冲，仅临界时出现；停止持续闪烁 |
| 连击 / 掉落 | 数字约 1.25s 后淡出，碎屑约 500–650ms，掉落球约 1.3s；不遮挡落点 |
| 通关 | 星级依次点亮；金色细环约 700ms 扩散 |
| 失败 | 触底瞬间一次约 280ms 横向细波，再淡入结算；不整屏震动 |
| 弹层 | 约 200ms 入场、150ms 退场；减少动态时省去位移 |

连击数字若正式加入，定义为连续有效消除的发射次数：一次发射中的消除与掉落合并计一次；无消除的发射清零；暂停、菜单与装填不清零。它是反馈计数，不增加倍率、不改变现有结算规则。

首页演示在前台自动循环；正式局内的连击、通关、失败只随真实事件触发。本次原型另有“局内动效”观察模式，会连续循环整套状态以便评审，生产游戏不加入自动弹出胜败页的行为。

所有位移与粒子遵循现有暂停、帧率与展示时钟。减少动态效果时保留文字和颜色，省掉粒子、环扩散与持续脉冲。静态球体纹理缓存，避免每帧重新生成材质；对比 4.7.0 同机同画质的帧时间，性能不允许因为纯视觉升级明显退化。

## 5. 仅 Windows 生效的技术路径

当前 Windows 发行包由 C# WinForms + WebView2 壳组成，`scripts/package-win.cjs` 编译 `windows/Program.cs` 和 `windows/LanService.cs`；当前 Windows 打包路径不使用 `electron/main.cjs`。原生验收以 WinForms 壳为准。

`npm run build:win` 执行 `tsc --noEmit && vite build --mode windows`，Vite 在该模式下以 `electron/windows-package.json` 作为前端版本源并输出到 `.build/windows/web`。实施时以 `import.meta.env.MODE === 'windows'` 启用 Windows 专属类、主题 CSS 与外观配置；不能只根据屏幕宽度、触屏能力或 desktop-ui 类判断 Windows。`npm run package:win` 会先运行上述构建，再执行 `node scripts/package-win.cjs`；打包脚本编译并运行原生壳测试程序，生成带 SHA-256 文件的 Windows ZIP。

建议改动位置：

| 文件 | 实施内容 |
| --- | --- |
| src/ui/windows-v5.css（拟新增） | Windows 专属色板、排版、按钮、首页、弹层覆盖 |
| src/ui/windows-home.ts（拟新增，或 home.ts 的 Windows 分支） | 首页结构，保留现有事件 ID、数据注入 |
| src/ui/home.ts、home-demo.ts/.css | Windows 5.0 移除重播；Android 5.0 按对应方案独立启用自动循环；4.7.0 行为需由旧版分支与测试覆盖 |
| src/render/windows-v5-appearance.ts（拟新增） | 外观参数；不改物理半径、棋盘坐标或规则配置 |
| src/render/board-artwork.ts、board-appearance.ts | Phaser 纹理与联机 Canvas 同步使用 Windows 外观；缓存纳入主题 key 或正确清理 |
| src/ui/next-orb-preview.css | 统一下一球材质；飞行期间严格沿用实际展示色 |
| src/ui/typography.ts、各菜单/结算/排行模块 | 套统一视觉骨架，保留焦点、分页和返回栈 |
| src/main.ts、src/game/PlayScene.ts、src/ui/lan-presentation.ts | 事件接反馈层，不改权威状态、计分与展示时钟 |

原有共享样式、Android 布局和默认渲染参数保持可用；Windows 专属分支缺省时必须得到 4.7 外观，不能全局覆盖 ORB_THEMES 后再补 Android。

双端目标版本均为 5.0.0，必须分别核对两个版本链路：
1. 当前 `scripts/package-win.cjs` 从根 `package.json` 取包版本，并要求它与 `electron/windows-package.json` 相等；Android 方案也将根版本用于 Android 构建。因此两端同时发布 5.0.0 时，根版本、Windows manifest 和 Android Gradle 目标需分别升到各自计划值，并逐一验证输出包名、原生程序集与 APK 的元数据一致。若将来希望 Windows、Android 不同版本独立发布，再让 Windows 打包脚本改为只读取 `electron/windows-package.json`。
2. 将 `electron/windows-package.json` 升为 5.0.0，`windows/app.manifest` 升为 5.0.0.0；原生程序集版本、输出目录、ZIP 文件名与校验清单都跟随 Windows 版本源。
3. Android 按对应方案将 Gradle `versionName` / `versionCode` 设为 5.0.0 / 50000，保留 `applicationId`、签名与数据。Android 与 Windows 各走各自构建/验收矩阵，不能用其中一端的构建结果代替另一端。
4. 保留已存在的 `最终交付/Windows/Orbbound-Windows-4.7.0`，新包输出独立 `最终交付/Windows/Orbbound-Windows-5.0.0` 目录；Android 旧数据与既有发行包也单独保留。
5. `scripts/publish-release.mjs` 当前从根 `package.json` 读取共同版本并发布两端资产。双端同时发布 5.0.0 时需先完成两端发布验收；若未来拆开发布时间，发布脚本也需支持选择平台和版本，不能让一端的待发状态覆盖另一端。

数据仍使用既有 %LOCALAPPDATA%/Orbbound、https://orbbound.local origin 和存储 schema，不做破坏性迁移。原生预览测试使用 --data-dir 独立目录，不读写用户真实存档。

联机协议计划保持 v3，规则与内容指纹应保持现值；必须实际重新计算并验证 4.7 ↔ 5.0 混连。视觉动画不得调整参与指纹的物理几何和展示调度时长；未经测试不能直接宣布兼容。

## 6. 分阶段实施与验收

1. 主题与首页：先完成 Windows 构建与版本源隔离，再定色板、字体、间距、卡片与自动循环，完成首页/局内/菜单的视觉一致性。
2. 渲染与反馈：同步 Phaser、联机 Canvas、DOM 下一球；完成发射、消除、风险、胜败与低动态。
3. 导航与持久化回归：三种单机、续玩、分页/筛选、模态来源、Esc、重复结算只记录一次、保存失败可重试、自定义键位。
4. Windows 原生验收与打包：正式写入 Windows 5.0.0 版本号，在隔离数据目录下完成 DPI/窗口/帧率检查，通过后生成 ZIP 与 SHA-256。

重点自动回归：`tests/home-demo.test.ts`、`tests/windows-platform.test.ts`、`tests/board-rendering.test.ts`、`tests/next-orb-preview.test.ts`、`tests/scene-preview.test.ts`、`tests/desktop-controls.test.ts`、`tests/shortcuts.test.ts`、`tests/modal-navigation.test.ts`、`tests/modal-pagination.test.ts`、`tests/viewport-shell.test.ts`、`tests/phaser-tween-clock.test.ts`、`tests/scene-lifecycle.test.ts`、`tests/scene-persistence.test.ts`、`tests/history-persistence.test.ts`、`tests/lan-presentation.test.ts`、`tests/lan-presentation-clock.test.ts`、`tests/lan-match-layout.test.ts`。首页现有测试直接断言点击/轻触重播文案；应按 Windows / Android 平台行为更新断言，同时保留两球切线和落点几何测试。

Windows 待验矩阵：
- 当前最小窗口 780×500，另测 1280×720、1366×768、1920×1080、2560×1440。
- 100% / 125% / 150% / 200% DPI、跨屏不同 DPI、最大化/还原、F11。
- 60 / 120 / 144Hz；失焦、最小化、暂停后恢复无补跑或计时漂移。
- 单机各模式、2–4 人联机、观战、旧存档、4.7/5.0 双向混连。

上述均为后续实施的验收要求。本文不代表这些矩阵已经全部验收，实际范围以发布验证记录为准。此前原型的浏览器布局观察不能替代正式游戏回归、原生 DPI/帧率、持久化与联机兼容验收。

## 7. 保留范围与边界

- 本轮以本文与 Android 配套修改方案为实施依据；UI 调整先提供真实界面样例确认，再继续正式发布。
- 首页自动循环、适度提饱和度、右侧工具、统一弹层与事件动效纳入双端 5.0.0 实现及验证范围。
- 评审循环、示例排行和简化棋盘不是正式游戏功能要求；正式实现须接入原有真实数据与导航。
- 5.0.0 实现、版本变更、发布资料与安装包分别核验；4.7.0 标签、源码基线与原交付包继续保留。
