# 4.4.0 验证记录

日期：2026-10-16。基线 `v4.3.1` / `2c2abef`。本版发布为测试版，保留 4.3.0 正式版；[实现方案](../design/4.4.0双端四人联机与界面优化方案.md)中的实体设备与平衡试玩门槛尚未全部完成。

## 共用规则与会话

- TypeScript 检查、Android 与 Windows 两套 Vite 生产构建通过。
- Vitest：36 个文件、395 项全部通过；包含单机、输入、存档、性能及联机回归。
- 新增四人规则测试覆盖 2 / 3 / 4 人、12 / 24 / 36 球阈值、其他存活选手贡献合计、同色与掉落去重、独立防御、队列容量、同批互抵、旧队列优先和阈值比例换算。
- 验证多人同批输入交换顺序后结果一致；封盘玩家保留竞分资格；同批淘汰、并列排名、弃权、到时与房主中断不产生虚假胜者。
- 会话与检索共 74 项测试，覆盖未满容量开局、满员拒绝、准备撤销、稳定身份、装载确认、并发申请、投票拒绝/取消/超时/重试、暂停额度、设置关闭确认、恢复倒计时、重连和非房主观战者退出。最终复核修正观战者退后台误取消在赛者投票，并验证其退后台、断线后已有投票仍保留且可获批准。
- 冻结使用逻辑时钟；暂停、设置和恢复期间清理旧待发输入。终局后迟到的冻结、关闭设置和开局消息不能恢复已经结束的比赛。
- 四人大消除表现按完整消息的实际 UTF-8 字节分包，应用预算 60 KiB，原生硬上限 65536 字节。快照先到、各玩家动画包后到时，使用各玩家独立进度，避免漏掉其他席位动画。
- 离房记录区分最终权威结果与未同步结果；未收到终局时保留本机成绩，不生成虚构名次。旧双人记录继续读取。

## 浏览器界面与输入检查

使用专门标明的开发 BroadcastChannel 模拟：桌面 960×680 与三个移动视口 320×568、390×844、412×915。此项验证共用界面和状态机，不代表真实 Android / Windows 网络或实体四机验收。

- 四人连锁对战：分步创建、默认容量四人、发现卡片人数、快捷填入、加入、准备、同步倒计时、分别发射、到时并列排名和结果页通过。
- 容量四人房间只加入两人，双方准备即可开始同图竞分；客人主动离开后，房主收到弃权并正常结算。
- 实际执行四人全员投票批准设置申请，只有申请者自动打开设置；所有端游戏时间冻结。修改画质后画布像素尺寸立即更新，关闭设置后仍等待全员准备，再共同倒计时恢复。
- 验证申请未获全员同意会超时，并返回明确提示；设置最长时限到期后会关闭设置并恢复流程。
- 对手全棋盘观察弹层可打开和返回自己，明确提示观察期间比赛继续；弹层阻止底层棋盘操作。
- 修正联机页面网格收缩和中文行高后，四个视口的对战、暂停投票及四人结果页均未发现可见容器纵向溢出（`scrollHeight <= clientHeight + 1`）。320×568 棋盘约 198.73×235.99 CSSpx，按钮和主要状态可达。
- 另检查 320×568 选关列表、关卡详情、练习和记录分页，未发现纵向溢出；桌面设置分类和选关流程可操作。
- Windows 联机使用桌面棋盘及键盘操作，隐藏移动双滑杆；浏览器实际发射与回归测试检查左右键松开发射、移出取消、设置弹层输入隔离、画质变化时清理旧手势。联机帧率信息独立上报。
- 布局检查使用 CSS 视口，不等同 Android dp、系统字体放大、真实输入法或 Windows 所有 DPI 缩放验收。主观动画录屏和 BGM 听测仍待实体游戏对局补齐。

## 原生服务互通

- 新增可重复运行的四进程驱动：`node scripts/lan-interop/test-four-peer.mjs`。
- 直接编译 Android 生产 Java `LanTcpService` / `LanFrameCodec` 与 Windows C# `LanService`，在桌面回环地址执行 Java 房主 + 三个 C# 客人，以及 C# 房主 + 三个 Java 客人。每个方向均同时保留三个独立客人，断开一个后其他两个继续传输。
- 两个方向合计 704 次数据交付、42 次控制交付，共 746 次 TCP 消息交付；数据字节总计 2,045,424。覆盖中文/emoji、精确 65536 字节帧、60 KiB 中文帧、顺序和断开隔离。
- 既有 Java/C# 双端驱动复测 176 次消息交付通过。
- 该测试证明原生服务可并发服务三个连接及编码/分帧正确，不包含四个实体终端、广播网络、真实 WebView 界面或完整会话协议的跨硬件验收。
