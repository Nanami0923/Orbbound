## 浏览器布局检查

开发期人工核查了普通模式的 320×568、320×240、568×320 等 CSS 视口：

- 320×568 首页演示、四个模式及底部三个入口可见；320×240 压力尺寸仍保留演示及主要入口，模式卡采用简化标签。
- 普通模式准备页自然收紧；设置分类首页紧凑，横屏详情保留固定顶部操作与一个正文滚动区。
- 教程执行 320×568 → 320×240 → 320×568 后，步骤节点数量前后均为 3，分页从 2 → 10 → 2，`data-page-overflow` 未标记异常；标题、正文、分页和操作区顺序已复查。
- Windows 构建模式核查 1280×720、640×360、800×600、1366×768、1920×1080：父选择区均为 `border-radius:0; overflow:visible`，全部入口在视口内、按钮中心命中成功，模式卡左上向内 6px 命中成功。记录为 `.build/qa-4.5.0/windows-browser.json`；这些 CSS 尺寸不等于原生 DPI 验收。

普通构建在 **320×568** 完成教程、设置、限时模式配置、练习各 **50 次往返，共 200 次**。逐次记录卡片和按钮的 `getBoundingClientRect()`、按钮中心 `elementFromPoint()` 命中及溢出状态，均未发现按钮越界、命中失败或分页溢出。教程重排最大 2.2ms，模式配置最大 2.6ms；该数值是当次布局执行耗时，不是完整打开延迟或 p95。

结果保存于 `.build/qa-4.5.0/browser-cycles.json`。横屏 568×320 只有人工布局检查，未执行相同的 200 次矩阵；当前记录也不证明所有事件监听器数量、长期内存或最终安装包已经完成压力验收。

## 分页异常注入

在 320×240 CSS 视口中移除 `Intl.Segmenter` 后，教程继续正常分页，关闭与翻页按钮可点击，实测该次重排约 6.6ms。再令 `document.createRange` 抛错，页面恢复三个原步骤和完整正文，关闭按钮保持可达；异常恢复区临时允许正文滚动。恢复浏览器 API 和 320×568 后，重新得到两页、三个步骤，异常标记清除并成功关闭。注入仅用于本地核查，完成后已还原。

## Windows 原生启动

原生程序启动后的可访问性状态读到 **4.5.0** 及旧存档内容，证明本次外壳能启动并访问已有数据。

原生截图出现 `FrameArrived` 超时，输入几何接口不可用。本轮没有把可访问性文本当成完整视觉证明，也没有修改系统 DPI；100% / 125% / 150% / 200%、780×500 最小外窗、跨 DPI 显示器移动及全部按钮命中矩阵仍待完成。

## Android 本版安装与真机复测

- Android 16 实体机使用原发行签名执行 `adb install -r`，从 4.4.0 覆盖到 **4.5.0 / 40500** 成功；首页演示可见，原无尽、限时存档仍被识别。
- 教程 → 练习 → 关闭返回正常，设置分类及声音详情可完整操作；联机创建两步和加入页面可打开、返回。
- 昵称和房主地址聚焦时，系统报告 `mInputShown=true`，WebView 可见高度由 **2608 → 1631 物理像素**；单字段编辑层和「完成输入」位于键盘上方且可达。完成输入或系统返回后，高度恢复到 2608，内容保留。这不是 CSS 视口尺寸，也不代表所有输入法组合都已验证。
- 手机当时没有连接可用局域网；创建 / 检索返回 `NO_LOCAL_NETWORK`，界面仍能退出并重新进入。没有完成真实 Android ↔ Windows 联机对局，不将明确的无网络结果记为网络互通通过。
