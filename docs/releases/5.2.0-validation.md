## 规则与联机

- 消息封装 v3；规则指纹 `7ca7ef0a`；内容指纹 `f942c2f9`。5.1 / 4.7 的旧规则指纹 `4e2a4139` 在 HELLO 和 WELCOME 两个方向均被拒绝，拒绝后房间只保留房主席位。
- 单机生成规则未改。联机个人初盘和新波次使用固定颜色配额全盘打乱，供球使用独立个人随机流；攻击行以目标身份及累计应用序号派生，不消耗供球随机流。
- 同机生产 Windows C# TCP/UDP 服务搭配真实 TypeScript `LanSession`，覆盖 2 / 3 / 4 人随机竞分和连锁对战六种组合：UDP 找房、发射、重连身份与完整快照一致、原个人状态保留、暂停恢复和自然结算均通过。
- 这些会话使用 `--time-scale 10` 受控时钟。竞分自然结算原因为 `all-sealed`，对战为 `knockout`；它们不是墙钟长时测试，也不是六组实体设备测试。

## 实际双设备联机

- 四人随机竞分由 Android 实机房主、Windows 打包原生客人和同机两名生产 C# headless 客人组成。有四名参与者、两台实体 UI 设备，不是四台独立实体终端。
- 开局四名玩家棋盘不同，权威初始状态已记录。真实全员暂停/准备继续、Android 观察对手后返回、实际发射和自然 `all-sealed` 结算通过；两端 UI 排名一致为 Windows 550、Android 170、另两名 90 / 50 分。
- 该局接受的发射次数分别为 Android 23、Windows 46、另两名各 23。Android 普通操作通过真实滑杆和发射按钮输入，Windows 通过真实鼠标输入；79 轮主驱动尝试不等同于 79 发成功发射。
- 两人连锁对战完全由 Android 实机与 Windows 原生程序完成。Android 使用沉浸触摸、Windows 使用鼠标，各接受 35 发，真实暂停/恢复和观战返回通过，自然 `double-knockout` 后双方均为第 1 名，两端显示一致；比分为 60 / 0，对战按淘汰顺序判名次。
- 两人脚本初次误沿用四人排名数量断言；已更正为两人，并从仍停留的两端真实结算页重新核验人数、排名和完整最终权威状态，原始失败记录另存。没有注入终局或更改成绩。
- 两种实体联机样本采集到的页面错误均为 0，并保存 Android 原生录屏。
