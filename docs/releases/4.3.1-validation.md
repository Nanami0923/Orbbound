# 4.3.1 验证记录

日期：2026-10-16。基线 `v4.3.0` / `9389dec`。本版实现双端检索更新、对战、表现与音乐修复，发布通道为测试版，保留 4.3.0 正式发布。

## 共用逻辑与回归

- TypeScript 检查和两套 Vite 生产构建通过。
- Vitest：33 个文件、313 项通过；包含原有单机、输入、存档和性能回归。
- 对战新增 22 项测试：11/12/24/38 球阈值和余量、单发上限、同色/掉落去重、先防御再同批互抵、队列上限、独立预告、3 秒间隔、自然下压保护、换波保留、双触底、截止优先、供球 RNG 隔离和快照验证。
- 30 项会话集成测试包含双方同批输入、重复包、冻结时清理未提交命令及重连事件水位；12 项发现会话测试覆盖扫描轮次、取消、迟到异常、多端点聚合、过期房间及不可信广告字段。
- 16 项表现/BGM 测试覆盖飞行、消除/掉落、下移、简化表现、事件去重、迟到收敛、重连基线、音效以及本地棋盘压力与场景切换。
- 3 项表现传输检查验证压缩弹道、两个同时大清盘和长时间补帧；事件加快照仍低于原生 65536 字节帧上限。
- CUA 检查发现 RAF 时间戳可能早于同帧发射的 `performance.now()`，旧预测插值会访问负下标。已改用有边界保护的路径插值，并补回归测试；15 项联机输入测试通过。
- 修复后的开发界面重新创建双端对战并各连续发射两次，预测路径的负下标异常未复现；两侧压力和操作冷却正常推进。

## 界面检查

- 使用明确标识的开发 BroadcastChannel 模拟，在 390×844 与 320×568 两个 iframe 上验证创建对战、房间发现、填入实际端口、保留昵称、刷新不覆盖手工地址、双方准备、同步倒计时、双方发射、消除计分/充能及认输结算。
- 同一波同角度首次三连均得到 30 分、3/12 充能；结算保留两侧实际发数，展示攻击统计。
- 320×568 对战棋盘容器约 225.68×267.99 CSSpx，攻击信息、对手预览与发射按钮可达；额外安全区可滚动。这不代表 Android dp 或真机触摸验收。
- 此浏览器流程验证共用界面，不替代真实跨设备 UI 对局。动画阶段和 BGM 压力另有直接控制器测试，未声称完成主观听测。

## 真实 Android 设备与 Windows 网络检查

在已连接的 Android 设备安装独立的 `.lantest` 测试包与 instrumentation 测试包，没有覆盖正式游戏、卸载正式包或清理正式存档。测试直接使用生产 `LanService`；Windows 对端是用生产 `windows/LanService.cs` 编译的独立测试宿主。

| 检查 | 实际结果 |
| --- | --- |
| Windows 房主，Android 客人，纯广播发现 | 首轮 8 秒发出 8 次广播查询，未收到应答；未通过 |
| Android 房主，Windows 客人，纯广播发现 | 同样未收到广播应答；未通过 |
| Windows 房主，Android 指定地址 UDP 检索 | 连续 10 轮成功；每轮创建新扫描并停止上一轮 |
| Android 房主，Windows 指定地址 UDP 检索 | 连续 10 轮成功；实际返回地址和 TCP 端口可连接 |
| 两个房主方向的 TCP 往返 | 中文/emoji 19 字节、精确 65536 字节、协议样例 36 字节均逐条校验成功；另有完成/关闭握手 |

广播与指定地址查询使用同一发现报文、生产原生服务和 UDP 端口；指定地址场景不通过 USB 转发。未修改系统防火墙、网络类型、VPN 或路由器设置。当前证据说明这组网络下单播可互通、广播未获回应，不能据此单独断定是路由策略、AP 还是系统过滤。

因此增加“按地址检索”入口：输入房主 IP 后查询实际房间端口，再快捷填入或加入；首次连接后，最近成功地址参与后续检索。此功能不会绕过设备间完全隔离。

测试过程中一次临时 TCP 探测使旧测试宿主误用已断开的首个连接 ID；测试宿主已改为按实际消息连接回复，重新执行后两个方向均通过。该问题位于测试驱动，生产 TCP 服务未出现同类故障。
