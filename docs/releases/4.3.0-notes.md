# Orbbound 4.3.0

Android 与 Windows 同步加入双人局域网联机，首发玩法为「同图竞分」。两台设备连接可互通的路由器或热点，一方创建房间，另一方加入；无需账号或互联网。

## 两端共用

- 首页新增「局域网联机」入口。Android 和 Windows 均可创建房间、加入房间；提供附近房间发现、刷新和手动输入 IPv4 地址与端口。
- 房主可设置房间名、简单 / 普通 / 困难，以及 3 / 5 分钟时长。双方准备后核验棋盘并倒计时开局；修改设置会清除准备状态。
- 新增双方分数、完成波次、比赛时钟、连接延迟和对手缩略棋盘。触底的一方保留分数并观看，另一方继续比赛。
- 房主统一处理双方发射、冷却、下压和结算；两端采用相同规则，发射冷却不依赖动画帧率或减少动态效果设置。
- 支持暂停申请、短时断线恢复、重新准备和再来一局；离开正在进行的比赛前需确认。
- 联机结果单独保存最近 100 局，并按结果标识去重；不写入单机排行，不推进闯关星级与解锁。

## 同图竞分规则

双方使用独立棋盘，同一编号波次具有相同初始棋盘和初始两球。保留三连消除、悬空掉落、发射压力和时间下压；清空棋盘后进入下一波并累计基础分。

比赛到时，或双方均触底时结算：先比较总分，同分比较完成波次，仍相同则平局。单方触底不直接判负。后续供球依据各自棋盘的有效颜色，操作不同会产生不同球序。

每人每局可以请求一次暂停，对方同意后最多暂停 30 秒。切后台或掉线时冻结对局，并尝试在 20 秒内恢复；一局最多 3 次自动恢复、累计等待最多 60 秒。恢复后双方确认，再倒计时继续。主动离开按认输处理；无法恢复的非主动中断不猜测胜者。

## Android

- 新增原生 TCP 传输与 UDP 房间发现，网络操作在后台线程执行，退出联机时释放连接、监听和发现资源。
- 优先选择 Wi-Fi / 有线局域网，不要求网络能访问互联网；手动连接按目标地址匹配子网，热点地址从有效网络接口获取。
- 前后台变化交给联机会话处理；房间和对局在前台时保持屏幕常亮。系统返回键进入联机退出确认，不沿用单机存档返回流程。
- 保留普通与沉浸触控方式，联机棋盘适配手机竖屏，对手信息独立展示。
- 当前目标仍为 Android SDK 36，仅增加网络状态查询权限；不额外申请定位或广泛存储权限。

## Windows

- 在现有轻量 WebView2 外壳中加入原生 TCP / UDP 服务，支持建房、发现、手动加入和连接清理。
- 联机中保留鼠标、键盘与自定义快捷键操作；输入昵称或地址时避免触发游戏操作。
- 最小化、锁屏或挂起交给联机冻结与恢复流程；房间关闭时释放端口和连接。
- 默认监听 TCP 42171、使用 UDP 42170 发现房间。TCP 端口被占用时自动使用其他端口并显示实际地址；UDP 不可用时仍可尝试手动加入。

## 安装、连接与验证范围

双方都应更新到 4.3.0；握手会检查协议、规则与内容版本。Android 更新时使用同签名 APK 覆盖安装；Windows 完整解压后运行 `Orbbound/Orbbound.exe`，继续使用系统 .NET Framework 4.8 与共享 WebView2 Runtime。

发现失败时可输入房主显示的 `IP:端口`。同一 Wi-Fi 下仍可能存在访客隔离、防火墙或热点限制；手动地址不能绕过设备间的网络隔离。Windows 首次建房可能需要在可信专用网络允许游戏通信。

本版实现范围为两人 IPv4 局域网同图竞分；不提供公网匹配、账号好友、房主迁移或进程重启后续局。连锁对战与协作接力仍属后续玩法，未在 4.3.0 开放。普通网页预览不提供真实原生联机。

自动测试与构建结果以 [4.3.0 验证记录](https://github.com/Nanami0923/Orbbound/blob/v4.3.0/docs/releases/4.3.0-validation.md) 为准。已完成的 Java / C# 原生传输互通测试运行在桌面真实 TCP 回环连接上；未完成 Android 真机、手机热点及不同设备组合的实测，不能将回环测试或浏览器模拟视作真机验收。
